### 1.1 远程执行的两个坑（**本窗口踩过，务必沿用**）

1. **PowerShell 传参会剥掉内层引号** → 远端复杂命令（含 `|`、`(`、中文、空格）必须走脚本文件：
   ```bash
   # 本地写 LF 脚本(末行留一行注释吸收尾部 CR) → scp → 远端执行
   [IO.File]::WriteAllText($f, ($txt -replace "`r`n","`n"), (New-Object System.Text.UTF8Encoding $false))
   scp -o BatchMode=yes "$env:TEMP\x.sh" Hermes:/tmp/x.sh
   ssh -o BatchMode=yes Hermes 'bash /tmp/x.sh'
   ```
2. **传中文绝不能走管道**（PowerShell 管道会 GBK 化并丢字节，实测 2132 字节只剩 2050）→ 必须 base64：
   ```powershell
   $b64 = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($msg))
   [IO.File]::WriteAllText("$env:TEMP\m.b64", $b64, (New-Object System.Text.UTF8Encoding $false))
   scp -o BatchMode=yes "$env:TEMP\m.b64" Hermes:/tmp/m.b64
   ssh Hermes 'base64 -d /tmp/m.b64 > /tmp/m.txt'
   ```
3. 本机到 GitHub 的连接**时通时断**（`git ls-remote` 偶发 21s 超时或连接重置）。离网时**自测套件会慢 8 倍**：
   `diagnose_push.py` 调 `git ls-remote` 撞 10s 子进程超时，6 个 `test_diagnose_*` 各耗 ~21s。
   这是**环境现象不是代码回归**（网络恢复后全量自测回到 19~24s）。

## 5. ⚠️ 微信投递在 `push_report.py` 里必失败（新发现）

`push_report.py` 的 `send_hermes()` 用**裸平台名**投递：

```python
cmd = [HERMES_COMMAND, "send", "--to", platform, "--file", "-"]   # platform == "weixin"
```

生产实测（`push_report.py --date 2026-10-27 --review-channel weixin --message …`）：

```
[失败] 微信: hermes send 退出码 1: hermes send: Weixin send failed:
iLink sendmessage session not ready: ret=-2 errcode=None
errmsg=prepare failed — the user must send the bot a message first (or re-pair)
```

改用**显式 target** 即成功（本次测试结果就是这样送达的）：

```bash
hermes send --to "weixin:o9cq809LX2IHhKGOWRtQQBNMZGi0@im.wechat" --file - < /tmp/msg.txt   # → sent, rc=0
```

`hermes send --list` 可列出全部可用 target（生产上有 1 个 weixin DM + 若干 feishu）。

**修法方向**（需决策：target 存哪）：给微信配一个可配置的显式 target —— 改 `push_report.send_hermes`
（按渠道查 target）+ `push_scope`（渠道配置）+ `.env`（如 `WEIXIN_TARGET=…`）+ 文档同步。
